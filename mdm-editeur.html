Notions de base

Concepts clés

MaDaMe est un métamodèle : les tables décrivent des objets métier, elles ne sont pas les objets. Cinq notions à connaître :

  • Objet — une entité métier (ex : « Engineering Item », « Vue »). Porte un nom, une nature, un domaine, éventuellement une discipline, et un statut.
  • Propriété — une définition d'attribut partagée, indépendante de tout objet. Elle se crée une fois puis s'affecte à autant d'objets que nécessaire. La modifier répercute le changement partout où elle est utilisée.
  • Affectation — le lien entre un objet et une propriété. C'est là que vivent les informations qui dépendent du couple objet+propriété plutôt que de la propriété seule : obligatoire ou non, discipline dans ce contexte précis.
  • Relation — un lien orienté entre deux objets : association, composition, agrégation ou généralisation.
  • Statut — brouillon (valeur par défaut) / validé / obsolète, pour piloter la curation d'un modèle importé.

Trois axes de classement d'un objet, indépendants et combinables :

  • Nature — son stéréotype/sa forme (Engineering Item, Vue, Document…). Ne fait pas hériter de propriétés.
  • Domaine — son regroupement fonctionnel dans l'organisation (PLM, Ventes, Qualité…).
  • Discipline — le métier technique concerné (ex : « 10 — Mécanique »), identifié par un code.

Saisie

Objets

Onglet Objet : nom, nature, domaine, discipline (code + nom si le code n'existe pas encore), définition métier.

  • Nature et domaine se créent à la volée si le nom tapé n'existe pas encore.
  • Retaper le nom d'un objet existant précharge sa fiche et le bouton devient « Mettre à jour l'objet ».
  • Suppression possible depuis la liste (onglet Fiches) — un message indique combien d'affectations et de relations seront aussi retirées.

Propriétés

Onglet Propriété : nom, type, description. Une propriété n'est affectée à aucun objet à sa création — voir l'onglet Affectation.

  • Type enum : indique le nom d'une liste de valeurs (créée à la volée), puis ajoute ses valeurs (code + libellé) dans le bloc qui apparaît.
  • Type grandeur : indique une grandeur physique (ex : Pression) et son unité (ex : bar) — réutilisables sur d'autres propriétés.
  • Multivaluée : caractéristique intrinsèque de la propriété (pas contextuelle à un objet).
  • Retaper un nom existant précharge sa définition et le bouton devient « Mettre à jour la propriété » — la modification s'applique partout où elle est affectée.
  • Suppression possible depuis la liste — elle retire aussi la propriété des objets qui l'utilisaient.

Affectation

Relie une propriété existante à un objet existant (tape leur nom exact, une liste de suggestions apparaît).

  • Obligatoire et discipline sont propres à cette affectation précise : la même propriété peut être obligatoire sur un objet et facultative sur un autre.
  • Si la discipline tapée n'existe pas, indique aussi son nom pour la créer.
  • Affecter une propriété déjà liée à cet objet met simplement à jour l'obligation/la discipline.
  • Pour retirer une propriété d'un objet : dans la liste Objets, clique la ligne de l'objet pour la déplier, puis « Retirer » sur la propriété concernée.

Relations

Lien orienté entre un objet source et un objet cible, avec cardinalités et type :

  • Généralisation — source = spécifique, cible = général (« la source hérite de / est un(e) la cible »).
  • Composition — la source est le tout, la cible la partie qui n'existe pas sans elle.
  • Agrégation — même idée, lien plus lâche (la partie peut exister sans le tout).
  • Association — lien simple sans notion de tout/partie.

Suppression possible depuis la liste Relations. Il n'y a pas d'édition de relation : supprime puis recrée si besoin.

Consultation

Listes (Fiches)

Trois listes cherchables et filtrables : Objets, Propriétés, Relations.

  • Recherche texte + filtres (nature/domaine/discipline pour les objets, type pour les propriétés/relations, statut partout) — cumulables.
  • Le statut s'affiche en badge coloré (brouillon = or, validé = vert, obsolète = gris) et se change directement dans la liste, sans ouvrir de formulaire.
  • Au-delà de 300 résultats, seuls les 300 premiers s'affichent ; affine la recherche pour voir le reste (pensé pour rester fluide avec des milliers de lignes).
  • Cliquer une ligne d'objet la déplie pour voir/retirer ses propriétés affectées.

Diagramme

Vue graphe interactive (Cytoscape) du modèle :

  • Recherche + Centrer pour localiser un objet dans un gros modèle.
  • Disposition : force dirigée (par défaut, s'en sort bien avec beaucoup de nœuds), hiérarchique, concentrique, cercle, grille.
  • Filtres par nature/domaine (repliables) pour masquer une partie du graphe.
  • Focus au clic : clique un objet pour estomper tout sauf son voisinage (réglable en nombre de sauts) ; clique dans le vide pour réinitialiser.
  • Afficher les propriétés : bascule chaque boîte entre nom seul (compact) et détail façon UML (nom, type, obligatoire ✱) — sans perdre la disposition en cours.
  • Plein écran pour explorer un gros modèle sur tout l'écran, avec tous les contrôles.
  • PNG/SVG pour exporter une image du graphe tel qu'affiché.
  • Légende des flèches : ▷ héritage · ◆ composition · ◇ agrégation · → association.

Fichiers

Ouvrir, enregistrer, télécharger

  • Ouvrir… charge un fichier .db SQLite conforme au métamodèle (voir metamodele.sql).
  • Nouveau modèle repart d'une base vierge avec le schéma complet.
  • Enregistrer réécrit directement le fichier ouvert si ton navigateur le permet (Chrome/Edge), sinon télécharge une copie.
  • Télécharger une copie force un téléchargement, sans toucher au fichier d'origine.

Astuces

  • Réutilise toujours le même nom pour une nature, un domaine, une discipline ou une propriété si tu veux qu'ils soient partagés — la casse compte (« Vue » ≠ « vue »).
  • Pour importer en masse (ex : depuis KNIME), vise les vues saisie_* de saisie.sql plutôt que les tables directement — elles gèrent la résolution par nom et les garde-fous.
  • Tout ce qui est créé arrive en statut brouillon — utilise les listes pour cocher au fur et à mesure ce qui est validé.
